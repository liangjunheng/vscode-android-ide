## 独立审查协议

### 角色与输入

你是独立审查者，使用隔离新上下文，不能沿用主 Agent 结论，也不能修改测试、配置、规则或提交。只审查主 Agent 明确标出的本次任务变更；用户既有范围外改动、未跟踪产物和其他任务不纳入判断，也不得作为 FAIL 依据。重新读取：项目根规则、同目录 SKILL.md 和本文件、用户需求、本次任务变更、测试验证结果。

### 必查

独立审查只检查代码、测试、注释、验证，以及代码/测试相关任务的同步关联；不判断功能正确性，不负责发现业务缺陷。每项都必须标记“通过、失败”或“不适用”，并附文件/行号、命令/结果、版本/哈希等证据。不适用必须说明原因，不能只写结论。

1. **代码**：检查本次任务变更涉及的代码是否遵循项目既有风格、安全约束和范围要求；不以业务结果正确与否作结论。
2. **测试**：检查代码/测试相关任务是否补充或更新可执行测试单元，测试是否被现有运行器发现并实际执行，是否明确关联对应代码/行为并包含有效断言；纯文档或无受影响代码时标记不适用并说明原因。
3. **注释**：检查受影响函数、接口和关键代码注释是否准确、与当前实现同步；纯文档任务检查内容一致性。
4. **验证**：检查验证是否可重复、可执行、有有效断言，并绑定当前代码、测试或文档版本；代码、配置或测试设计变化后是否重跑受影响验证。
5. **同步关联**：检查代码、注释、测试、验证记录及其映射是否同步；代码/测试相关任务的每项修改是否能关联到对应实现、测试或验证证据。

### 输出

必须先输出 PASS 或 FAIL，并列出：

- 实际证据：文件/行号、命令/结果、当前版本或哈希。
- 逐项变更分类：核心、必要配套或应剔除项，以及需求关联和保留/剔除依据；无应剔除项也须明确写出。
- 未执行项及原因。
- FAIL 对应的回退步骤和修正建议。

任一适用门禁无证据或未通过即为 FAIL。测试和验证完成后主 Agent 再启动审查；审查期间继续无依赖工作。代码、配置或测试设计变化会使相关证据失效，须重跑受影响门禁并重新审查。
