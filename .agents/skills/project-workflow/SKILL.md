# 项目强制工作流

本 skill 是通用工作流正文；项目专属约束只来自目标项目规则。调用后先自动初始化，再按以下门禁执行。有效凭证仅为本轮宿主提供、来源为 harness:project-workflow-guard 且匹配当前会话、轮次和文件哈希的 HOST_WORKFLOW_RECEIPT。它只证明规则已检查并注入，不证明业务门禁或业务正确性；无效或缺失时不得报告加载成功。

## 自动初始化

- Agent 从本 skill 目录定位 harness/bootstrap.mjs，探测宿主、当前项目和可用 Node.js；通过 DSH_PROFILE_DIR 识别 Harness profile，必要时只传入已核实的 --profile / --project。
- 只做必要探测和本 skill 注册；保留已有规则与配置。无项目规则时仅生成通用入口，不复制源项目约束。安装器须备份并幂等维护自己的 marker。
- 配置成功不等于加载成功；必须确认后续原生回执对应当前项目和文件。已有有效配置不重复安装或改写。宿主、运行时或权限不支持时报告具体阻塞，不猜 profile、不绕过权限、不声称所有 IDE 自动支持。

## 门禁

1. **需求**：明确需求、验收标准、假设和边界；不清楚先询问。
2. **分析**：先索引相关复现路径及测试/验证方式,逐项记录入口、前置条件、操作步骤、预期结果、测试位置/命令及成功/失败判据,并关联需求、实现和调用链；再比较方案、风险、范围与验证成本。缺失或不可用项须说明并补齐,未完成不得实现。
3. **测试设计**：逐项核验分析索引中的复现路径和测试/验证方式,确认前置条件、步骤、预期结果及成功/失败断言准确、可执行且覆盖目标行为；遗漏或无效项须补齐或修正,不得仅登记。实现前仅核验设计,不得执行测试或独立审查。纯文档改动做内容一致性检查；影响配置、生成代码或行为的改动不适用此例外。
4. **实现**：
   - **范围**：采用范围受控方案,仅保留直接服务需求、根因或验收标准的核心及必要配套改动；测试、文档和配套须说明关联,不得删除或恢复用户原有范围外改动。
   - **根因与禁令**：修复根因及状态、依赖时序、所有权和生命周期关系。禁止用特例、硬编码、平台/调用方/测试特判、代次标识(Generation/token/序号过滤)、延时投递(delay/post)、盲目重试或轮询、堆叠状态标志、静默跳过/丢弃结果、捕获吞错/默认值伪成功、扩大超时、强制刷新重建、过度串行化、延迟释放/泄漏资源、重复执行、关闭或削弱检查/测试等方式掩盖或绕过问题；不得以必要性放行资源泄漏、吞错伪成功、静默丢弃必要结果、错误重复执行或削弱检查/测试。
   - **注释**：新增/修改函数须有准确中文注释,说明职责、输入输出、前置条件、结果和功能点。
   - **测试**：逐项核验分析索引及测试设计,确认实现覆盖对应复现路径,测试/验证方式与当前实现匹配；所有新增/修改点须关联可执行测试,严格断言相关行为,不得仅调用或登记。路径或方法变化须同步索引、设计和映射；实现及同步完成后在测试/验证门禁逐项执行并记录结果,未验证不得通过或交付。
5. **同步**：核对当前工作区及受影响调用链，包括未修改但被调用的函数；同步修正说明、调用链、测试映射并执行对应测试。
6. **测试**：实现和同步完成后，先跑直接相关测试，再跑受影响模块测试；覆盖正常、边界、异常和结果。测试须被现有运行器发现执行，不能扩大生产 API 或绕过安全约束。无可执行测试须说明原因，不得视为通过。
7. **验证**：测试通过后按影响范围执行编译、格式、静态检查等；代码或测试设计变化会使相关旧证据失效，必须重跑。验证必须可重复、可执行、有断言，并绑定当前内容或版本。
8. **独立审查**：测试和验证完成后，仅启动一次隔离审查角色；主 Agent 不得代替。主 Agent 必须明确提供本次任务的变更范围和验证证据；审查读取相对路径 REVIEWER.md、任务范围内变更和验证结果，逐项输出 PASS/FAIL、证据、未执行项和修正建议。审查采用异步结果驱动：主 Agent 启动后保留任务句柄，不同步等待或高频轮询；有其他无依赖工作时继续处理。收到完成事件后恢复并处理结果；若无其他工作，结束当前轮，由宿主事件恢复，不得重复启动同一审查。任务句柄显示异常、结束或丢失且未提供有效结果时，报告阻塞并回收该任务；未收到有效结果不得虚报 PASS/FAIL。审查失败须回退到对应门禁。
9. **交付**：只有所有适用门禁、测试、验证和当前变更对应的独立审查明确返回 PASS，且无无关本任务改动时才可报告交付完成；独立审查未返回、返回 FAIL 或处于阻塞状态时，必须明确说明未通过项、未执行项、范围外阻塞和剩余风险。用户明确要求提交时，可在保留上述说明的前提下创建 commit；创建 commit 不得表述为门禁通过或验证完成。

源码、配置或测试设计变化后不得沿用受影响旧证据；不得覆盖、还原或混入用户改动；未经明确要求不得新增 hooks、CI、脚本或工具。不得将 skill 加载视为门禁通过。

## 验证追踪

每个用户 BUG/功能至少保留一个成功的可执行回归方法，并写入对应函数中文注释：功能点、位置、复现方式、执行条件和成功证据。多函数可共享但须逐函数关联；受影响函数即使未修改或未直接调用也必须执行对应方法。方法、覆盖功能或调用链变化时同步映射并重跑；历史成功、工具存在或命令成功不替代当前证据。未记录、未同步或未执行不得交付。

可移植插件、安装器和测试位于本目录，复制与启用见 README.md；复制不等于注册，必须取得实际回执。
